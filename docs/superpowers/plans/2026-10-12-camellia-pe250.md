# Camellia PE250 Implementation Plan

**Goal:** Support PEAR-first Camellia extraction, verify 10,000 supplied pairs, and run all 89,915 pairs under `jobs/`.

**Architecture:** A dedicated scRNA assembly module validates paired IDs, limits input before PEAR, and associates assembled sequences with original R2 barcode prefixes. Existing extraction and downstream stages retain their output schemas.

**Tech stack:** Python 3.11, Pixi, PEAR 0.9.6, pytest, existing pandas and darlin-core dependencies.

## Verified results

The full suite passed all 62 tests. The 10,000-pair fixture produced 9,761
assembled pairs and 3,260 extracted reads, with nonempty downstream outputs.
The initial full job completed successfully: 89,915 input pairs, 87,967 assembled
pairs, 28,223 extracted reads, and 116 final rows across 87 cells with 2,746
UMI counts. Full-data outputs and `summary.json` are under
`jobs/scCamellia-pe250/`. A read-only code review found no concrete bugs.

The full job was subsequently rerun with `--reads-cutoff-per-molecule 10`.
Current results contain 24 final rows across 23 cells with 57 UMI counts;
all 58 denoised rows have at least 10 reads. Assembly and extraction counts
remain the same. The job script, README, and summary record the new cutoff.

## Decisions

Use original read lengths (300 bases in supplied files), PEAR default assembly parameters, eight threads unless overridden, and the first 10,000 pairs for the fixture. Normalize IDs using their first token and terminal mate suffix. Preserve original R2 CB/UMI values even when assembly changes the sequence. Do not positionally join assembled reads with raw R2, reuse stale assembly outputs, or process unassembled pairs.
